# ADR-0005: Three.js 3D 적용 (문 통과 모드부터)

* **상태:** 채택
* **날짜:** 2026-10-10

## 배경

화면이 더 입체적이고 동적이면 아이의 집중도가 높아질 것으로 기대합니다. HTML 환경에서 3D를 쓰는 방법을 검토한 결과,
전체를 3D로 바꾸기보다 **속도감이 가장 중요한 문 통과 모드부터 3D로 만드는 것**이 효과 대비 부담이 가장 적었습니다.

## 결정

* **Three.js r149 (UMD 빌드, 전역 `THREE`)** 를 CDN에서 불러옵니다
  * r160부터는 ES 모듈 전용이라 빌드 도구 없이 `<script>`로 쓰기 어렵습니다. 빌드 도구를 도입하면 최신 버전으로 올립니다
* **규칙과 화면을 분리합니다**
  * 규칙 · 판정: `web/src/game/modes/gate-mode.js` (`GateScene`)
  * 화면: `web/src/game/views/gate-view-2d.js` (Phaser 2D), `gate-view-3d.js` (Three.js 3D)
  * 3D 모드(`gate3d-mode.js`)는 `createView()`만 바꿔 같은 규칙을 3D로 보여 줍니다
* **두 캔버스를 겹칩니다:** Three.js 캔버스(뒤) + 투명한 Phaser 캔버스(앞: HUD, 파티클, 팝업)
* **2D 문 통과는 유지합니다:** 저사양 기기나 3D를 불러오지 못한 경우를 위한 대안

## 개정 (2026-10-10): 문 통과 2D/3D 를 하나로

* 사용자 피드백: "문 통과와 3D 문 통과는 겹친다" → 메뉴의 놀이는 **문 통과 하나**만 둔다
* `GateScene.use3D()`: Three.js 를 불러왔고 WebGL 을 지원하면 3D 뷰, 아니면 2D 뷰를 자동으로 고른다
* 예전 저장값 `gate3d` 는 `A.MODE_ALIASES` 로 `gate` 에 이어 준다 (`modes/gate3d-mode.js` 삭제)

## 3D 화면 구성

* 도시 위 하늘 다리를 달리는 3인칭 시점 (히어로 뒷모습)
* 다가오는 유리문, 오답 시 3D 유리 파편과 다리 아래 추락 → 거미줄 복귀
* 대시 때 시야각(FOV) 확대로 속도감, 안개(fog)로 깊이감, 창문이 빛나는 빌딩

## 결과

* 판마다 3D 자원(형상, 재질, 텍스처, WebGL 컨텍스트)을 해제해 메모리가 쌓이지 않게 합니다 (`GateView3D.destroy`)
* 다른 모드도 3D가 필요하면 같은 방식(규칙 + 뷰 분리)으로 3D 뷰만 추가합니다
* 캐릭터는 아직 2D 그림을 3D 공간에 세운 스프라이트입니다. 3D 모델(glTF)은 Phase 2 검토 사항입니다
