# ADR-0006: "게임이 먼저, 문제는 파워업" — 히어로 러너 시험 놀이

* 날짜: 2026-10-17
* 상태: 시험 중 (아이 반응을 보고 확정 · 확장 여부 결정)

## 배경

사용자 피드백: "너무 단순해서 그런가 흥미를 가지지 않네". 기존 6개 놀이는 연출은 많지만 구조가 모두 **"문제를 보고 보기를 고른다"** 로 같다.
아이가 직접 조작해서 재미를 느끼는 순간(뛰기 · 피하기 · 모으기)이 거의 없고, 문제 풀이가 곧 게임 전부라서 "움직이는 그림이 붙은 퀴즈"로 느껴진다.

검토한 원인 (추정): 조작 재미 부족 · 목표가 안 보임 · 매 판 같음(우연 · 보상 없음) · 시작 전 선택이 많음 · 난이도 불일치.

## 결정

1. **문제가 없어도 재미있는 기본 조작**을 먼저 둔다 — 버튼 하나(점프)로 하는 러너. 상자 넘기 · 밟기 · 코인 모으기 · 2단 점프
2. **문제는 벌칙이 아니라 강해지는 수단** — 정답 구슬을 점프로 잡으면 다음 달리기 구간 동안 파워업(거대화 · 무적 별 · 자석 · 코인 비, 무작위)
3. **짧은 판** — 러너는 6문제(약 1~2분). "한 판 더"를 쉽게
4. **학습과 무관한 실수는 벌주지 않는다** — 상자에 부딪히면 잠깐 느려질 뿐. 하트는 문제에서만, 한 문제에 최대 1개
5. 기존 놀이는 그대로 두고 **새 놀이로 시험** → 메뉴 맨 앞(NEW), 처음 한 번은 미리 골라 둔다 (`runIntroduced`)

## 결과 · 다음 판단

* 아이가 러너를 기존 놀이보다 오래 · 자주 하면 → 같은 구조를 넓힌다: ② 모험 지도 · 스테이지(별 3개) ③ 판 끝 보물 상자(무작위 보상) ④ 버튼 하나로 바로 시작 ⑤ 자동 난이도
* 반응이 없으면 → 원인을 다시 본다 (난이도 · 선택 피로 · 테마 등). 아이가 실제로 한 놀이 · 그만둔 지점 · 한 말을 기록해 판단
* 구현: `web/src/game/modes/run-mode.js`, 수치 `A.RULES.run*`, 기반 훅 `questionCount()` 추가 ([game-design 3.7](../planning/game-design.md))
